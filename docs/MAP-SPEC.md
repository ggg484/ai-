# 地图规格 · 沙线（Sandline）

> 三线布局的战术爆破图，尺寸 72 × 64 m，两个包点，T 在南、CT 在北。
> 当前是**全 AABB 灰盒**：所有几何都是轴对齐盒子，碰撞体与视觉几何一一对应。
> 这个约束让骨架期可以用最简单的碰撞，但它也是要换掉的东西——本文档说明怎么换。

---

## 1. 坐标与朝向

- 单位：米
- **Y 向上**，地面 y = 0
- **玩家朝 +Z 时 yaw = 0**（T 出生朝北看，所以 T 的 yaw 是 0）
- 相机 yaw 需要 `+Math.PI` 修正（`game.js` 的 `_updateCamera()` 里做了）

整体范围：

| 轴 | 范围 |
|---|---|
| X | -36 … +36（72 m） |
| Z | -32 … +32（64 m） |
| 外墙高 | 6 m |
| 内部墙高 | 4 m |


三条进攻线：

| 线 | 路径 | 长度 | 特点 |
|---|---|---|---|
| **A 大** | T 出生 → 东侧走廊（x 19…32）→ A 点 | ≈ 52 m | 长直道，狙击位强，掩体多 |
| **中门** | T 出生 → 中路（x -7…7）→ 中门 → A 短 / B 门 | ≈ 46 m | 最短，但中门是死亡漏斗 |
| **B 洞** | T 出生 → 西侧走廊（x -32…-19）→ B 点 | ≈ 52 m | 窄，转角多，适合近战 |

**三线长度刻意做成接近**（46–52 m，跑速 5 m/s → 9.2–10.4 s），
这样 T 无论打哪条线，CT 从出生点转点的时间窗口都差不多。

## 4. `buildMap()` 的数据契约

`game.js` 依赖这个返回结构，改地图时**字段不能少、不能改名**：

```js
{
  world: World,                  // 碰撞世界
  sites: {                       // 包点
    A: { x, z, r },
    B: { x, z, r }
  },
  spawns: {
    player: { x, y, z, yaw },    // 玩家出生
    bots: [{ x, z, yaw }, …]     // 5 个 Bot 出生（数量要和 game.js 对上）
  },
  buyZone: { minX, maxX, minZ, maxZ },
  bounds: { minX, maxX, minZ, maxZ },   // 雷达绘制范围
  waypoints: [{ x, z }, …],      // Bot 巡逻路点
  callouts: { … }                // 预留：报点名称，当前未使用
}
```

**加 Bot 数量**要同时改两处：`map.js` 的 `spawns.bots` 和 `game.js` 里
`this.bots = this.map.spawns.bots.map(...)`——后者是 map 出来的，所以只改 `spawns.bots` 就够。
但路点数量决定了巡逻路线密度，5 个 Bot 配 14 个路点是当前配比。

## 5. 改地图的四种操作

### 5.1 加一个掩体

```js
box(cx, cy, cz, w, h, d, kind, { tag: 'cover' });
```

- `cy` 是**中心高度**，不是底部。1.5 m 高的箱子，`cy = 0.75`
- `tag` 只影响射线返回值和 `overlaps()` 的忽略过滤，当前用 `'wall' | 'cover' | 'platform' | 'ground'`
- `collide: false` 时只画不碰撞（远景楼用这个）

**掩体高度建议**：

| 高度 | 用途 | 蹲下能躲吗 |
|---|---|---|
| 1.1 m | 半身掩体，站着露头 | 能 |
| 1.5 m | 全身掩体，站着不露头 | 能 |
| 2.2 m | 高掩体，需要绕 | 能 |
| 0.3 m | 台阶/平台，可直接走上去 | — |

台阶能不能走上去取决于 `MOVEMENT.stepHeight = 0.36`。**高于 0.36 的台阶走不上去**，
必须做成斜坡或加二级台阶。

### 5.2 开一个门洞

墙是 AABB，开洞只能**切段**。以 A 点西墙（x=15，原 z 8…28）为例：

```js
// 想留 z 10..14（A 短）和 z 22..26（CT 连接）两个洞
// 剩下的实体段：z 8..10（中心 9，长 2）
//               z 14..22（中心 18，长 8）
//               z 26..28（中心 27，长 2）
[[9, 2], [18, 8], [27, 2]].forEach(([cz, len]) => {
  box(15, 2, cz, 1, 4, len, 'brick', { tag: 'wall' });
});
```

**洞的净宽 = 相邻两段之间的空隙**。上面第一个洞净宽 = 14 - 10 = 4 m。

### 5.3 改包点位置

改 `sites` 和地面标记两处（标记在 `buildMap` 末尾用 `PlaneGeometry(9,9)` 画）：

```js
const sites = {
  A: { x: 26, z: 18, r: 5.8 },
  B: { x: -26, z: 18, r: 5.8 }
};
```

`r` 只影响 `Round.siteAt()` 的下包判定和雷达圆圈，**不影响地面标记的大小**。
要同步改标记，去改 `mA.position.set(...)` 那几行。

### 5.4 加一条新通道

1. 在 `map.js` 里用 `box()` 摆墙
2. 在 `waypoints` 里补 2–3 个点，让 Bot 会走
3. 开 `?cam=top` 看俯视图，确认没有意外封死
4. 走进新通道，确认 `world.move()` 不卡角（贴着墙斜着走）

## 6. 关卡设计约束（改图前先读）

这几条是从 CS 的经典图反推出来的，违反了图就会「不好玩」，而且很难归因。

### 6.1 视线长度

| 位置 | 建议最大视线 | 当前 |
|---|---|---|
| A 大（长枪线） | 45–55 m | ≈ 52 m |
| 中门（步枪线） | 30–40 m | ≈ 34 m |
| B 洞（近战线） | 15–25 m | ≈ 22 m 分段 |

**视线超过 60 m 会让步枪失去意义**（AK 在 90 m 处伤害衰减到 65%，打不死人）；
**低于 12 m 会让狙击失去意义**。

### 6.2 掩体间距

同一条线上，相邻掩体之间留 **6–10 m**。太密变成「蹲坑图」，太疏变成「对枪图」。
当前 A 大的箱子在 `(27,-3)` 和 `(23,-15)`，间距约 12 m，偏疏——这是可以改的。

### 6.3 包点必须有两个以上入口

A 点当前入口：A 大（南）、A 短（西，z 10..14）、CT 连接（西，z 22..26）。
**三个入口**，CT 可以从两个方向回防。这是对的。

只有一个入口的包点会变成「谁先到谁赢」，不要这么设计。

### 6.4 出生点不能互相看见

T 出生 (0, -28) 到 CT 出生 (0, +26) 有中门墙 + 中门楣挡住。
如果你把中门拆了，两个人一出生就能对枪——**这是最典型的改图事故**。

验证方法：`?cam=top` 看不出遮挡关系，要在 T 出生点朝 +Z 看，确认看不到 CT 区。

## 7. 换成正式几何的路径

AABB 灰盒的局限：不能做斜面、不能做圆柱、不能做拱门、视觉和碰撞必须一致。

### 7.1 推荐路径：glTF 视觉 + 自动生成 AABB 碰撞

```
Blender 建模
  ↓ 导出 scene.glb（整个关卡一个大文件，或按区域拆）
  ↓ 每个碰撞体单独命名，前缀 col_
  ↓ 导出时勾选「Apply Modifiers」
three.js 加载
  ↓ 遍历 gltf.scene，找 name.startsWith('col_') 的 mesh
  ↓ 读它的 boundingBox，转成 {minX,…} 塞进 world
  ↓ 其余 mesh 合并成静态批次
```

关键点：**碰撞体和视觉体分离**。一堵有装饰线条的墙，视觉是 2000 面，
碰撞是一个盒子。这样既好看又快。

```js
// 伪代码，加在 map.js 里
const gltf = await loadGLTF('assets/maps/sandline.glb');
const colBox = new THREE.Box3();
gltf.scene.traverse((o) => {
  if (!o.isMesh) return;
  if (o.name.indexOf('col_') === 0) {
    o.geometry.computeBoundingBox();
    colBox.copy(o.geometry.boundingBox).applyMatrix4(o.matrixWorld);
    world.add({
      minX: colBox.min.x, maxX: colBox.max.x,
      minY: colBox.min.y, maxY: colBox.max.y,
      minZ: colBox.min.z, maxZ: colBox.max.z,
      tag: o.userData.tag || 'wall'
    });
    o.visible = false;
  }
});
```

**坑**：glTF 的 Y 轴向上、单位是米，和当前一致；但 Blender 导出默认会把 +Y 转成 -Z，
要在导出设置里选「+Y Up」并确认朝北的方向。

### 7.2 不要做的事

- **不要用三角网格做碰撞**。`world.move()` 是 AABB 专用的，换网格碰撞要重写整个移动系统。
- **不要一个 mesh 一个 draw call**。正式关卡会有几百个物件，必须按材质合批（`mergeGeos()` 已有）。
- **不要保留灰盒的 52 个碰撞体再叠加新的**。会重复碰撞，人物会被弹开。

### 7.3 分阶段替换

不要一次性换完整张图。按这个顺序：

1. A 大走廊（一条直道 + 3 个掩体）—— 验证管线
2. A 点（平台 + 掩体 + 三个入口）—— 验证高低差
3. 中路（门洞 + 门楣）—— 验证开洞
4. B 洞 + B 点 —— 复制 A 的经验
5. 外墙与远景 —— 最后做，不影响玩法

每换一块，`?cam=top` 对比灰盒版本，确认**通道宽度、包点位置、出生点距离**没变。
变了就等于换了张图，所有 Bot 路点和数值都要重调。

## 8. 性能预算

| 指标 | 灰盒现状 | 正式版上限 | 超了怎么办 |
|---|---|---|---|
| draw call | 48 | 120 | 按材质合批、用实例化 |
| 三角形 | 5,932 | 250,000 | 加 LOD、剔除远景 |
| 碰撞体 | 52 | 400 | 合并相邻共面盒 |
| 材质数 | 7（6 种 kind + 标记） | 20 | 合并到图集 |

`world.raycast()` 是**线性遍历所有碰撞体**。52 个的时候无所谓，
400 个的时候每发子弹要测 400 次 slab 相交——那时需要加空间划分（均匀网格或 BVH）。
**骨架期不要提前优化**，但要知道这条线在哪。
