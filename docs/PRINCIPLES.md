# 最高准则（凌驾于其他一切文档之上）

> 这份文档只有两条。
> 任何设计、任何任务、任何"先这样吧"的妥协，都必须先过这两条。
> **与此冲突的方案一律作废，不需要讨论工期。**

---

## 准则一 · 移动端是最高准则

### 1.1 一句话

**这是一个手机游戏，不是"能在手机上跑的 PC 游戏"。**

所有功能先想移动端怎么做，再想键鼠怎么做。顺序反了就是错的。

### 1.2 硬性要求

| 编号 | 要求 | 判定方式 |
|---|---|---|
| M-1 | **任何功能都必须有对应的移动端实现** | 没有触屏操作路径的功能 = 未完成，不得合并 |
| M-2 | **不存在"仅 PC 可用"的功能** | 代码里出现 `if (!isTouch)` 包裹整块玩法逻辑 → 直接打回 |
| M-3 | **操作定义顺序：先触屏，后键鼠** | 新操作的 PR 必须先在描述里写清触屏映射，再写键鼠映射 |
| M-4 | **触控热区 ≥ 44×44 CSS px**，相邻热区间距 ≥ 8 px | 真机截图测量，或用 `?touchdebug=1` 覆盖层 |
| M-5 | **主要操作落在拇指可及区**（屏幕下 2/3、左右各 1/3） | 横屏双手握持，拇指自然覆盖范围 |
| M-6 | **性能基线是移动端中端机**，不是开发机 | 见下方 1.4 性能预算 |
| M-7 | **必须适配安全区**（刘海、圆角、手势条） | `applySafeArea()` 已写入 CSS 变量，新 UI 必须用 `var(--safe-*)` |
| M-8 | **必须横屏**，且横屏两侧都要能玩（左手/右手习惯） | `orientation: "landscape"` 已声明，UI 不得假设单侧 |

### 1.3 触屏映射的既有事实（骨架已实现，别推翻）

当前 `js/core/input.js` 的映射是全项目基准，扩展时保持同一套词汇：

| 玩法动作 | 移动端 | 键鼠 |
|---|---|---|
| 移动 | 左半屏虚拟摇杆（推满 = 跑，半程 = 静步） | WASD，Shift 静步 |
| 视角 | 右半屏拖动 | 指针锁定鼠标 |
| 开火 | 右侧 `fire` 按钮（支持按住连发） | 左键 |
| 跳跃 | `jump` 按钮 | Space |
| 蹲下 | `crouch` 按钮（切换式，不是按住） | Ctrl / C |
| 换弹 | `reload` 按钮 | R |
| 切枪 | `switch` 按钮 | 1 / 2 / 滚轮 |
| 下包 / 拆包 | `use` 按钮（长按） | E（长按） |
| 购买 | 全屏面板，大按钮，不用下拉框 | B |

**蹲下在移动端是切换式而不是按住**，因为按住蹲会占掉一根手指，玩家没法同时移动+开火。
这个决定是移动端优先的典型例子——PC 上按住蹲更精确，但移动端必须让步。以后遇到同类冲突，
**一律按移动端改，PC 端跟随**。

### 1.4 移动端性能预算（硬指标）

基准机型定义为：**骁龙 7 系 / 天玑 8000 系 / A14 及以上，2021 年后中端机**。

| 指标 | 预算 | 超标处理 |
|---|---|---|
| 渲染分辨率 | 1080p 逻辑分辨率，`?dpr` 上限 2 | 由 `mobile-perf.js` 接管，不得绕过 |
| 帧率 | 目标 60 fps，**不得低于 45 fps** | 掉到 45 以下必须降档，不许"下个版本优化" |
| p95 帧时间 | ≤ 22 ms（60fps 预算 16.6ms + 抖动余量） | 超了就是不合格 |
| Draw call | ≤ 120（骨架现在 48，有 2.5 倍空间） | 材质合批 / 图集 / 实例化 |
| 三角面 | ≤ 250k（骨架现在 5.9k） | LOD + 剔除 |
| 显存 | ≤ 180 MB | 纹理压缩（KTX2 / Basis） |
| 首屏可玩 | ≤ 8 s（中端机 4G） | 主包瘦身 + 分包懒加载 |
| 内存占用 | ≤ 400 MB（防 iOS Safari 杀进程） | 对象池 + 及时 dispose |

**测法**：真机 + Chrome Remote Debugging，或 `?stats=1` 在真机上读数。
**开发机跑出的帧率不算数。**

### 1.5 移动端验收清单（每个任务收尾必填）

复制到 PR / 任务卡里，缺一项不算完成：

```
[ ] 触屏能完成这个功能的全流程（不是"能点"，是"能玩"）
[ ] 单手/双手握持都能操作，没有必须换手的步骤
[ ] 热区 ≥ 44px，无误触（连续操作 20 次不出错）
[ ] 刘海屏 + 手势条机型上 UI 不被遮挡
[ ] 中端机帧率 ≥ 45fps（附帧率截图）
[ ] 手机发热 10 分钟后不掉帧
[ ] 断网 / 切后台 / 来电中断后能恢复
```

## 准则二 · 质量优先

### 2.1 一句话

**可以慢，不许糙。工期不够就砍范围，绝不砍质量。**

### 2.2 为什么这条是硬的：营收结构决定

这款游戏的商业模式是 **卖枪皮、刀皮**，不是卖广告、不是卖体力、不是卖关卡。

这意味着：

- 玩家付钱买的是**眼睛看到的东西**——第一人称视角模型（viewmodel）的每一个面、每一条高光、
  每一帧检视动画。
- 皮肤是玩家**每天盯 40 分钟**的资产。视角模型占屏幕右下 1/4，粗糙一秒，付费意愿归零。
- 皮肤的经济价值建立在**稀缺感 + 精致感**上。低多边形风格可以成立（如 Valorant），
  但**"凑合"的风格永远卖不出钱**。
- 所以：**对局可以简化，皮肤管线不能简化。** 宁可少 3 张地图，也要把枪皮做到能卖。

### 2.3 质量标准分层

不是所有东西都要 3A 级，但每一层都有下限，**不许跌破下限**：

| 层级 | 对象 | 标准 | 不可妥协的点 |
|---|---|---|---|
| **L0 变现资产** | 枪皮、刀皮、手套、检视动画 | **最高标准，无上限** | PBR 全通道、法线细节、磨损遮罩、指纹/划痕、镜面反射真实、检视动作有重量感、切枪动画 0 穿模 |
| **L1 玩家高频可见** | 第一人称手部、武器本体（默认皮肤）、准星、命中反馈 | 高 | 手部解剖正确（不能是方块）、无穿模、光照与场景一致、开火动画有后坐 |
| **L2 场景主体** | 墙体、地面、掩体、包点 | 中高 | 材质无平铺接缝、无拉伸、法线正确、光照烘焙一致、无 Z-fighting |
| **L3 场景配景** | 远景、天空、装饰物 | 中 | 不抢视线、不掉帧、不糊成一团 |
| **L4 临时占位** | 骨架里的程序化材质、Bot 模型 | 低（**仅限 M0-M1**） | 必须打 `PLACEHOLDER` 标记，M2 结束前全部替换 |

**当前骨架全部是 L4。** 这是允许的，但 M2（美术垂直切片）的验收标准就是：
**L1 和 L2 层全部脱离 L4**。

### 2.4 具体质量门槛（可测量，不靠感觉）

**材质**
- 每张材质必须齐备：Albedo / Normal / Roughness / Metalness / AO（五通道，缺一不算完成）
- 平铺必须用世界坐标 UV 或三平面投影，**肉眼在 2 米内看不到重复**
- 法线强度与光照方向匹配，不允许"贴上去像贴纸"

**视角模型（最关键）**
- 三角面预算：主武器 8k–15k，刀 5k–10k（这个预算足够做到精致，不需要低模）
- 骨骼：至少 3 段（手臂-手腕-武器），支持检视动画
- 材质：金属件必须 metalness 0.85+ 且有 roughness 变化贴图，木件必须有纹理走向
- **必须过"三距离检查"**：贴脸（0.3m）、正常（0.5m）、检视（0.25m 旋转）三个距离都不穿模、不掉细节

**动画**
- 开火、换弹、切枪、检视，四个动作缺一不可（皮肤卖点就在这四个动作上）
- 动画曲线必须有缓动，**不许线性插值糊过去**
- 换弹时手部动作要"抓得住"弹匣，不许穿模

**画面**
- 无 Z-fighting（远处墙面闪烁）
- 无接缝（墙与地交界处不能有缝）
- 无穿模（视角模型不穿墙——已用 `depthTest: false` + `renderOrder: 1000` 解决）
- 光照统一：同一个场景里不允许两种色温

### 2.5 质量闸门（里程碑制）

每个里程碑结束设**质量门**，不过门不进下一阶段：

| 门 | 位置 | 通过条件 |
|---|---|---|
| **G1** | M1 结束（手感内核） | 移动/射击/后坐力/命中判定在真机上"像 CS"，10 名玩家盲测 7 人以上认可 |
| **G2** | M2 结束（美术切片） | A 大一面墙 + 一把 AK 达到 L1/L2 标准，做 4K 截图对比原版，肉眼差距 ≤ 20% |
| **G3** | M3 结束（完整对局） | 完整 5v5 一局能打完，无阻断性 bug，真机 45fps |
| **G4** | M4 结束（适配） | 8 台真机（含 2 台低端）全部通过移动端验收清单 |
| **G5** | M5 结束（联机） | 10 人同房 30 分钟无掉线，延迟 < 120ms 时手感无明显劣化 |
| **G6** | 上线前 | 皮肤管线可量产：一件新枪皮从建模到进游戏 ≤ 3 人日 |

### 2.6 冲突裁决顺序

出现冲突时，从上往下，**上位覆盖下位**：

```
1. 平台硬规则（审核不通过 = 游戏不存在）
2. 准则一 · 移动端（做不了手机 = 不配上架）
3. 准则二 · 质量（糙 = 卖不动皮肤 = 项目死）
4. 功能范围（可以砍功能）
5. 工期（最后才动）
```

**工期永远排最后。** 如果排期表说"这里来不及了"，答案是砍功能，不是降标准。

### 2.7 什么时候允许"先糙"

只允许一种情况：**这段东西永远不会被玩家看到。**

- 内部调试工具 → 可以糙
- 临时验证脚本 → 可以糙
- 灰盒碰撞体（玩家看不见的）→ 可以糙

只要会被玩家看到、听到、点到，**一律不许糙**。

## 附：这两条准则怎么落地到日常

1. **每个任务卡必须有"移动端实现"栏**，空着不算完成任务（见 `TASKS.md` 的 DoD）。
2. **每次提交必须附截图/录屏**，PC 截图不算，要给移动端截图或真机录屏。
3. **每两周一次质量评审**，拿 4K 截图和原版对比，不达标就返工，不进入下一阶段。
4. **新来的同学第一份要读的文档就是这份**，不是 ARCHITECTURE。
