# 上架流程：从空工程到玩家能下载

> 所有命令都在 `game/`（工程根，含 `.builda-agent/`）里执行。
> 官方原文：`docs/官方主题/md_agent_publish.md`、`md_agent_manifest.md`。

## 0. 先理解两件事

| 概念 | 含义 |
|---|---|
| **草稿（draft）** | `builda publish` 把包传到服务器并同步到 App 的「待发布」区。这一步只对你自己可见 |
| **公发（release）** | 你在 Builda App 里点发布、过审后，玩家才能下载。CLI 不能代替这一步 |

所以「上传成功」只代表**当前 Builda 版本已更新**，不代表上线。

## 1. 自检

```bash
cd game
./.builda-agent/builda check
```

输出里重点看：

- `builda-agent-skill-updated=1` → 工具链刚更新，**重新读一遍 `.builda-agent/SKILL.md`** 再继续
- `engine=...` → 引擎识别（本包是 `h5`）
- `sdk=...` → SDK 版本；没有就 `builda sdk install`
- `cloud-state=attention` → 有云端设计建议，按提示 `inspect`；`pass` 就不用管

## 2. 授权（只需一次）

```bash
./.builda-agent/builda auth
```

- 会拉起浏览器授权；**不要把 token / cookie / 密码贴给任何人**，也不需要手动复制
- 凭据存在 `$HOME/.builda-agent/`，不在项目里
- 换账号：`builda auth --force`

## 3. 确认引擎

```bash
./.builda-agent/builda engine detect .
# engine=h5   engine-upload-support=available
```

只会是 `godot | h5 | unity | unknown`。`unknown` 时不要硬传，先确认工程根对不对。

## 4. 生成/检查商店清单

首次：

```bash
./.builda-agent/builda new-manifest
```

然后编辑 `builda.publish.json`，**这五个字段必须在发布前填好**：

| 字段 | 规则 |
|---|---|
| `category` | 28 个英文 key 选一个（`action` `strategy` `rolePlay` `plot` `adventure` `sandBox` `survival` `pzzle` `mystery` `leisure` `simulation` `yangCheng` `card` `desktop` `tower` `rogueLike` `shoot` `speed` `sport` `fangZhi` `music` `dress` `other` `cooperation` `moba` `asymmetric` `party` `fight`）。注意拼写就是 `pzzle`，不要改成 `puzzle` |
| `languages` | 游戏**真实支持**的语言，BCP 47（如 `["zh","en"]`）；空值会被拒 |
| `minChromeMajor` / `minIOSMajor` | 正整数，填**实测能跑的最低版本**；填高了会挡掉老设备玩家。纯 H5 基线是 `81` / `15` |
| `orientation` | `landscape` 或 `portrait`，要和游戏画面一致 |
| `engine` | 由 `new-manifest` 自动写入，不要手改 |

`title` 只是「首次提审时可能被预填的名字候选」，不会覆盖 App 里已发布的名称；封面、简介、宣传图都在 App 里改。

## 5. 构建

```bash
npm run build        # 本包示例：把 index.html / game.js 拷进 dist/
# 换成你自己的构建：vite build / Cocos 构建 / Godot 导出 / Unity Build
```

产物要求见 `02-包规范与拒收清单.md`，核心只有一句：**zip 根就是 `index.html`**。

## 6. 打包

Linux / macOS / WSL：

```bash
cd dist && rm -f ../builda-web.zip && zip -r ../builda-web.zip . && cd ..
```

Windows：不要用 PowerShell 5.1 的 `Compress-Archive`（会写 `assets\icon.png` 这种反斜杠条目，服务端按 zip-slip 拒收）。
用 7-Zip：

```powershell
7z a -tzip builda-web.zip .\dist\*
```

## 7. 校验（上传契约，不是建议）

```bash
./.builda-agent/builda bundle-check --engine h5 builda-web.zip
```

期望：

```
bundle=ok
bundle-engine=h5
sdk-injected=ok
```

Godot 还要加 `--webview-compatible`。报错就改导出配置或 SDK 引用，**不要绕过**。
超过 50 MiB 会出现 `bundle-size-hint`，只是优化提示，不阻断。

## 8. 发布草稿

```bash
./.builda-agent/builda publish builda-web.zip
```

它内部依次做：`upload-build` → 等服务器 `ready` → `create-draft`（首次）/ `update-draft`（已有 `game.json`）。

阶段心跳：`uploaded` → `validating` → `promoting` → `ready`。
**只有退出码 0 才能说「当前 Builda 版本已更新」**；不要看到 100% 上传就报成功。

## 9. 在 App 里试玩、提审、公发

1. 打开 Builda App → 创作中心 → 待发布 → 找到刚同步的版本
2. 真机试玩（支付、广告、音频、安全区这些只有真机才准）
3. 提交审核；通过后点发布
4. 发布后玩家才能搜到/下载

## 10. 更新版本

改代码 → 重新构建 → **同一条命令**：

```bash
./.builda-agent/builda publish builda-web.zip
```

有 `.builda-agent/game.json` 时自动走 `update-draft`，不会新建游戏。

## 11. 断网、重试、会话配额

| 情况 | 正确做法 |
|---|---|
| 网络中断 / CLI 退出 / 机器重启 | **原样重跑同一条 `publish` 同一个 zip**。CLI 按 bundle SHA-256 续传，自动换新凭证 |
| 想「重新打包再传」 | 不要。重打包会改 SHA-256，等于开新会话，不能续传 |
| `409 upload session quota exceeded` | 每个游戏 1 个活跃会话、每个账号 3 个。先 `builda upload-list [--all] --json` 看谁占着，确认废弃再 `upload-cancel <session>` |
| `canCancel=false` | 先 `upload-status <session>`，不要强清 Validator 租约 |
| 校验失败 / 4xx | 按提示修包，不要重试同一份坏包 |

## 12. 需要额外资源时（可选）

只在这些情况用 `assets.zip`：

- 音频走平台/FMOD 通道（`audio/**`：`.mp3 .ogg .wav`）
- 大资源动态加载（`res/**`：模型、大图、视频、AssetBundle、数据型 `.pck`）

```bash
./.builda-agent/builda assets check assets.zip
./.builda-agent/builda assets upload assets.zip
```

| 限制 | 值 |
|---|---|
| 压缩包 | 默认 340 MiB（老游戏可由服务端放宽到 500 MiB） |
| 解压总量 | 1024 MiB |
| 单文件 | 32 MiB |
| 文件数 | ≤ 10000（zip 条目 ≤ 20000） |

上传成功后清单里会写入 `assetsVersion/assetsBaseUrl/assetsManifestUrl`；游戏里用
`Builda.assets.url("res/...")` 取地址，**不要硬编码 CDN**。

## 13. 发布前检查表

- [ ] `builda check` 无阻断
- [ ] `builda engine detect .` 与清单 `engine` 一致
- [ ] `category` / `languages` / `minChromeMajor` / `minIOSMajor` / `orientation` 已填
- [ ] `dist/` 根目录就是 `index.html`，且 `<head>` 有 `<script src="builda-sdk.js"></script>`
- [ ] zip 里没有 `node_modules/`、`.map`、`.env`、工程源文件
- [ ] `bundle-check` 返回 `bundle=ok`
- [ ] 本地 `builda dev` 能玩；真机草稿能玩
- [ ] 知道「草稿 ≠ 上线」，已准备去 App 提审
