# 路线图（从骨架到上线，再到长期运营）

> 这是「以后的计划」的唯一权威版本。
> 它把 [`plan/沙城协议_立项计划书_v0.1.md`](plan/沙城协议_立项计划书_v0.1.md) 里的 M0–M6 排期，
> 与 [`PRINCIPLES.md`](PRINCIPLES.md) 的两条准则、[`SKIN-PIPELINE.md`](SKIN-PIPELINE.md) 的营收要求合并。
> **两者冲突时，本文件更新，计划书作为依据保留。**

## 0. 全景

```
M0 骨架 ✅  →  M1 手感  →  M2 美术+皮肤  →  M3 完整对局  →  M4 移动端适配  →  M5 联机  →  M6 上架  →  M7 内容运营
   (已完成)     2 周        3 周(含皮肤)       3 周            2 周            4 周        1 周        持续
```

每个阶段末尾有一道**质量门**，不过门不进下一阶段。
门的定义在 `PRINCIPLES.md` §2.5，这里给每道门补上具体的交付物与判定人。

| 阶段 | 工期 | 交付物 | 质量门 | 判定标准 |
|---|---|---|---|---|
| **M0 骨架** | ✅ 已完成 | 可玩灰盒（当前代码） | — | 冒烟测试全绿 + bundle-check 全绿 |
| **M1 手感内核** | 2 周 | 4 把枪的弹道、移动手感调校、Bot 静态靶 | **G1** | 3 名老 FPS 玩家盲测，≥2 人说"像 CS" |
| **M2 美术 + 皮肤切片** | 3 周 | A 大 + 中门成品材质、AK 真模型与皮肤管线 | **G2** | 与原版并排盲评 ≥80% 相似；一把 AK 皮肤能改 wear/seed |
| **M3 完整对局** | 3 周 | 经济/购买/回合/投掷物/5v5 Bot/记分板/结算 | **G3** | 完整 MR12 一局不崩；Bot 能独立下包拆包 |
| **M4 移动端适配** | 2 周 | 三档机型调优、触屏布局定稿、设置、存档、多语言 | **G4** | 8 台真机全部通过移动端验收清单（`PRINCIPLES.md` §1.5） |
| **M5 联机 5v5** | 4 周 | Room 权威、快照、预测回滚、重连、匹配 | **G5** | 2 台真机 10 分钟无掉线；p75 RTT ≤150ms |
| **M6 上架** | 1 周 | manifest、rankBoards、皮肤 IAP、提审 | **G6** | bundle-check ok；草稿可完整玩一局；审核无阻断 |
| **M7 内容运营** | 持续 | 皮肤批量生产、赛季、排行榜 | 每批皮肤 | 单件皮肤从建模到进游戏 ≤3 人日 |

**总量**：约 101 人日（M0 已消耗约 6 人日），M2 因加入皮肤管线从 2 周加到 3 周。

## 1. M1 · 手感内核（2 周）

### 目标

让"移动和开枪"这件事本身成立。**这是射击游戏的地基，地基本身就是产品。**

### 做什么

| 项 | 落点 | 验收 |
|---|---|---|
| 补齐 4 把枪 | `js/config/weapons.js` 加 `m4a4 / awp / deagle` | 数值与计划书 §4 的 9 枪表一致 |
| 后坐力图谱 | `recoilPattern()` 改为手写曲线（AK 的 30 发弹道要能背下来） | 对着墙打一梭，弹孔形成可学习的 T 形 |
| 移动手感调校 | `js/player/controller.js` + `MOVEMENT` | 急停、连跳、贴墙滑、静步，四项都要"有感觉" |
| Bot 静态靶模式 | `js/game/bots.js` 加 `mode: 'static'` | 用于练枪与回归测试 |
| 命中判定精修 | `_hitscan()` 的头部球/身体胶囊比例 | 爆头率在合理区间（不是随缘） |

### 不要做

- 不要碰美术（M2 才做）
- 不要碰联机（M5 才做）
- 不要加新玩法（手雷、拆包都在 M3）

### 质量门 G1

3 名有 CS 经验的玩家，各玩 15 分钟，回答三个问题：

1. 移动像不像？（急停、连跳、静步）
2. 压枪能不能学会？（打三个弹匣后能否把弹着点控制在人形内）
3. 愿不愿意再玩一局？

**≥2 人三个问题都答"是"才算过。** 不过就继续调，不进入 M2。

## 2. M2 · 美术 + 皮肤垂直切片（3 周，本项目最关键的一个阶段）

### 为什么这个阶段最长

两个原因叠加：

1. 它决定**游戏长什么样**（材质、光照、氛围）
2. 它决定**游戏能不能赚钱**（皮肤管线通不通）

**这两件事必须在同一个阶段做完**，因为皮肤材质必须和场景光照在同一套 PBR 参数下调，
分开做会导致"皮肤浮在场景上"。

### 做什么（按顺序，不要并行）

**第 1 周 · 场景材质**

- A 大长墙、地面、中门通道三处换成真材质（`ART-PIPELINE.md` §2）
- 光照重做：方向光角度、色温、雾、环境光遮蔽
- 目标：截图能让人认出"这是沙城风格"

**第 2 周 · 武器与皮肤管线**

- Blender 建 AK 中模（8k–15k 面，3 段骨骼）
- 写 `SkinMaterial`（`SKIN-PIPELINE.md` §2.1）
- 替换 `js/render/viewmodel.js` 的 `buildRifle()`
- 支持 `?skin=&wear=&seed=` 三个参数
- 做完这一周，**"手是方块"的问题自动消失**

**第 3 周 · 氛围与打磨**

- 道具（箱子、油桶、贴花、电线）
- 天空与远景
- 音效替换（枪声、脚步、换弹）
- 用真机跑一遍，确定性能基线

### 质量门 G2

| 检查 | 标准 |
|---|---|
| 场景相似度 | 与原版截图并排，盲评 ≥80% 认为"同一风格" |
| 皮肤机制 | 改 `wear` 能看到漆层剥落；改 `seed` 图案位置变化 |
| 视角模型 | 0.3m / 0.5m 双距离不穿模；与 CS 同款皮肤差距 ≤20% |
| 性能 | 中端机 ≥45fps；draw call ≤120 |
| 材质完整性 | 每张材质五通道齐备（albedo/normal/rough/metal/AO） |

**这一关不过，不要做 M3。** 因为 M3 会加大量玩法，玩法加完再回头改管线，成本翻倍。

## 3. M3 · 完整对局（3 周）

### 做什么

| 周 | 内容 |
|---|---|
| 1 | 经济系统完整化（连败补偿、半场交换、加时）、购买菜单重做（分类/预览/快捷键） |
| 2 | 投掷物（HE/闪光/烟雾/燃烧）、拆包、C4 交互细节 |
| 3 | Bot 战术 AI（买枪、转点、下包、拆包、听声辨位）、记分板、结算页、观战 |

### 质量门 G3

- 完整 MR12（先到 13 分）一局，从买枪到结算，**中途不崩、不卡死、不穿帮**
- Bot 能独立完成一次"下包 → 守包 → 被击杀"的完整链路
- 玩家死亡后能观战，不黑屏

## 4. M4 · 移动端适配（2 周）

> **这个阶段不是"适配"，是"以移动端为准重做一遍交互"。**
> 准则一要求：不是把 PC 的东西塞进手机，是按手机重新设计。

### 做什么

| 项 | 内容 |
|---|---|
| 触屏布局定稿 | 摇杆位置/大小、按钮排布、透明度，按 8 台真机实测 |
| 灵敏度曲线 | 提供 3 档预设（低/中/高）+ 自定义，含开镜灵敏度独立系数 |
| 三档画质 | 低/中/高，自动检测机型推荐（`engine.setQuality()` 已有骨架） |
| 设置页 | 画质、灵敏度、音量（交给平台）、语言、准星自定义 |
| 存档 | `privateKV` 存设置与皮肤拥有状态 |
| 多语言 | 中/英，文案抽到 `js/i18n/` |
| 中断恢复 | 切后台、来电、断网 → 回来能继续（利用 `appVisibility`） |

### 质量门 G4（最严的一关）

8 台真机，覆盖：

- 2 台低端（骁龙 6 系 / 天玑 700，2020 年机型）
- 4 台中端（骁龙 7 系 / 天玑 8000 / A14）
- 2 台高端（8 Gen 2 / A17）

**每台都要过 `PRINCIPLES.md` §1.5 的 7 项清单。**
低端机允许 30fps，但**不允许操作失灵**。

## 5. M5 · 联机 5v5（4 周）

技术方案已在 [`NETCODE.md`](NETCODE.md) 写死，不要重新设计。

| 周 | 内容 |
|---|---|
| 1 | Room 建连、房间流程、服务端 tick 骨架（10Hz 起） |
| 2 | 玩家状态同步、快照插值、本地预测（移动） |
| 3 | 射击判定（服务端权威）、命中回滚、延迟补偿 |
| 4 | 重连、掉线处理、匹配、双端真机联调 |

### 质量门 G5

- 两台真机同房 10 分钟，无掉线、无卡顿尖峰
- p75 RTT ≤ 150ms 时，"打中了"和"看起来打中了"一致率 ≥ 90%
- 一人断网 10 秒后重连，能回到对局

**降级路径**（如果 Room 实测不达标）：5v5 → 3v3 → 1v1 → 合作 Bot。
按顺序降，不要跳。

## 6. M6 · 上架（1 周）

| 项 | 内容 |
|---|---|
| manifest | `builda.publish.json` 补齐 `rank` / `iap` 声明 |
| rankBoards | 排行榜接入（先在 `builda.publish.json` 声明） |
| 皮肤 IAP | 至少 3 件可购买皮肤（1 枪 1 刀 1 手套），走平台 IAP |
| 包体 | `bundle-check` 全绿；首包 ≤200MiB |
| 提审 | 草稿试玩、隐私政策、年龄分级、素材 |

### 质量门 G6

- `bundle-check` 返回 `bundle=ok`
- 草稿在 App 内能完整玩一局（不是"能启动"，是"能打完"）
- **皮肤能买、能装备、能进游戏显示**（这条最容易漏，因为它跨了三个系统）

## 7. M7 · 内容运营（上线后，持续）

这才是真正赚钱的阶段。技术上要提前准备好：

| 能力 | 上线前要有 | 说明 |
|---|---|---|
| 皮肤热更新 | ✅ | 皮肤走 `assets.zip` 分包，不进主包，可以单独更新 |
| 皮肤参数配置 | ✅ | `meta.json` 驱动，改数值不用重新打包 |
| 稀有度体系 | ✅ | 消费级/工业级/军规级/受限/保密/隐秘，六档 |
| 磨损区间 | ✅ | 每款皮肤声明 `wearRange`，控制供给 |
| 图案种子 | ✅ | `patternSeed` 决定花纹位置，制造"独一无二" |
| 赛季机制 | 可选 | 赛季皮肤、段位奖励 |
| 交易/市场 | **不做** | 涉及金融合规，不碰 |

**内容节奏建议**：上线首月 8–12 件皮肤（够开箱池），之后每月 4–6 件。
按 `SKIN-PIPELINE.md` §4 的 3 人日/件算，需要 1 名专职美术。

## 8. 资源变体（人不够怎么办）

上面的排期假设"1 名开发者 + AI 协作"。如果资源不同：

### 只有 1 个人（当前假设）

按 M1 → M2 → M3 → M4 → M6 走，**跳过 M5 联机**，先上单机 Bot 版。
Bot 版一样能卖皮肤（玩家在训练场也能看枪），先回收成本，联机作为 2.0。

### 2 个人（1 程序 + 1 美术）

并行：程序做 M1/M3，美术做 M2。M2 会提前到第 3 周开始。
总量从 101 人日压到约 70 人日（并行 + 减少返工）。

### 3 个人以上

拆成"玩法线"和"资产线"两条，M5 联机可以提前到 M3 之后并行做。
但**质量门不能并行跳过**——G2 不过，资产线不许批量生产。

---

## 9. 每个阶段都要守的三件事

1. **移动端可玩**：任何阶段结束时，手机上都要能完整玩一遍。不允许出现"这个版本手机上跑不了"。
2. **包体不失控**：每次合并前 `bundle-check`。当前 0.2 MB，预算是 45 MB（主包），
   到 30 MB 就要开始警惕。
3. **冒烟测试全绿**：`npm run smoke`。它会跑移动/射击/击杀/下包/结算全流程。
